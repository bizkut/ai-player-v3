Version: 0.4.6
Date: 2026-11-25
  Changes:
    - Targets Factorio 2.1 (factorio_version "2.1"); Factorio 2.1 refuses to
      load mods declaring 2.0.
    - New "opencode" provider: the bridge calls OpenCode Go (or pay-as-you-go
      via OPENCODE_BASE_URL) directly with OPENCODE_API_KEY from bridge/.env.
    - The bridge sends a stable x-opencode-session header per run, so turns
      share one session and reuse the prompt cache.
  Bugfixes:
    - Bridge startup no longer deletes request files unless the mod confirms
      (via rcon.print) that its pending queue was cleared; an unconfirmed
      clear previously orphaned a pending request and left the AI idle for
      5 minutes.

Version: 0.4.5
Date: 2026-11-25
  Bugfixes:
    - gather travels to the nearest source within 256 tiles when none is
      within 40, instead of only naming its position (the AI looped for
      minutes needing stone without going to get it).
    - build_smelter's "need stone" failure says to gather stone.

Version: 0.4.4
Date: 2026-11-25
  Bugfixes:
    - insert/take without an "inventory" now find a lab's science-pack slot
      and a turret's ammo slot; inserting where nothing fits says which
      inventories exist instead of "no building with a 'nil' slot".
    - research reports the technology already being researched (progress and
      science packs it needs) instead of queueing unrelated technologies on
      every call. A named technology is queued or the reason it can't be is
      given (already researched or queued, trigger, missing prerequisites);
      another one is never substituted.
    - Bridge responses lost the research "tech", build_miner "resource" and
      deposit_to_chest "keep" parameters: research ignored the requested
      technology and build_miner always mined iron-ore.

Version: 0.4.3
Date: 2026-11-25
  Features:
    - build_power skill: places offshore-pump -> boiler -> steam-engine at the
      water nearest the unpowered machines, fuels the boiler, and runs
      small-electric-poles to every electric machine without power. Later
      calls extend the existing grid.
    - loot_chests also collects the output of furnaces/assemblers the AI
      placed (smelted plates stayed in the furnaces). In co-op the human's
      machines are never emptied.
    - /ai-claim marks machines with no recorded builder as the AI's, for
      co-op saves started before 0.4.3.
    - perception.research.trigger_techs lists the trigger technologies the
      force can complete next and what each needs.
  Bugfixes:
    - The AI's hand-crafting now counts as production, so craft-item trigger
      technologies unlock (automation-science-pack: craft a lab).
    - research reports the real research trigger instead of telling the
      model to hand-craft automation-science-pack before it is unlocked.
    - Failed crafts say why: recipe locked, machine-only, or which base
      items are short and where finished ones are waiting.
    - gather, build_miner and fuel_all failures name the nearest target
      beyond their radius with a goto position.
    - \uXXXX escapes in bridge responses are decoded; non-ASCII text arrived
      as "u2014".
    - The "last turn" summary resets every turn, so one bridge fallback no
      longer repeats in every prompt.

Version: 0.4.2
Date: 2026-08-29
  Features:
    - Remote interface: get_chat lets an external harness poll the mod's
      chat ring buffer directly (no python bridge needed).
    - Remote interface: import_blueprint stages a blueprint string as entity
      ghosts at a position (build_blueprint, falling back to manual
      entity-ghost creation on Factorio 2.0 where the 1.x API path returns
      nothing).
    - Remote interface: export_blueprint captures a rectangle of the world
      to a blueprint string.

Version: 0.4.0
Date: 2026-07-16
  Features:
    - Remote interface: query/list_queries expose a read-only query registry
      (get_recipe, get_resource_patch, can_place, nearest_buildable,
      inspect_entity, get_enemies, get_character_state) for external callers,
      alongside the existing skill/primitive surface.
    - Remote interface: run_primitive lets external callers (e.g. an MCP
      client) invoke the same Tier-0 actions (place, mine, craft, set_recipe,
      insert, take, chat) the autonomous bridge LLM uses.
  Changes:
    - perception.lua: extracted describe_entity() so inspect_entity returns
      exactly what the autonomous router sees.
    - primitives.lua: exported placement_problem/DIRECTION_MAP for can_place.
